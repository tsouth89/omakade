## Maintainer checklist for the exact candidate

Use a backup of personal library data before testing restore. Keep the archive
and recovery folder private. Record candidate commit, package checksum, Omarchy
version, display/scaling, and controller model with the results.

1. Browse Desktop and Couch Mode with keyboard, mouse, and controller. Exercise
   reconnect, input handoff, filters, an empty result, and return from a real game.
   Check focus visibility, readable text, scrolling, and reduced motion.
2. Add a real native game and a supported desktop entry. Edit arguments and working
   directory, launch, restart, then remove the entry and confirm game files remain.
3. Link two installations, choose a default, restart, and launch it. Disconnect its
   drive or disable its source; verify fallback and restored preference on return.
   Add/remove a GOG root and check missing-root diagnostics without file deletion.
4. Apply cover, hero, and transparent logo images. Restart and reset one slot.
   Bulk-edit a filtered group, apply a saved filter, and pick a random game. Confirm
   the selection is inspectable and no game launches until Play is chosen.
5. Export and preview a backup. In an isolated test profile, test merge and replace,
   close/reopen, and verify choices, manual paths, artwork, and local account setup.
   Test an invalid archive and confirm it leaves existing data unchanged.
6. For Steam Input, first test a non-Steam shortcut in Steam, then launch the same
   Steam entry from Omakade. Record the compatibility selection, controller input,
   exit, and return. Do not infer success from shortcut discovery alone.
7. Complete versioned real-library reports for available native/Flatpak sources
   and the exact ARM64 package on supported hardware. Record unavailable setups
   explicitly under SBS-1113 / GitHub #9 and SBS-1115 / GitHub #13.
